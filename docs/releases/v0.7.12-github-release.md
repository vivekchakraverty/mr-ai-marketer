A generated post can be edited where it is written, and a Mastodon post's hashtags now render
as Mastodon renders everyone else's.

## Fixed: the AI disclosure broke Mastodon's hashtag bar

Mastodon lifts a post's hashtags out of the body and shows them as chips underneath — but only
when they are the last line. Its own `hashtag_bar.tsx` walks back from the end and gives up at
the first thing that is not a hashtag: "if the last line only contains hashtags". Anything after
them, including a single short sentence, leaves every tag inline in the text.

The disclosure line was appended to the end of the post, after the hashtags, so every disclosed
post rendered inline while other people's showed chips. The generator is told hashtags are
Mastodon's primary discovery mechanism and duly ends on them, which is exactly what the
disclosure then displaced.

It now goes immediately before that trailing hashtag block instead. It is no less visible one
line earlier, and the rule it satisfies is about the post saying plainly that a machine wrote
it, not about where in the post the sentence sits. Only a line that is *nothing but* hashtags
counts as that trailing block, which is the same test Mastodon applies — a hashtag inside a
sentence is left alone, and a closing thought written under the tags keeps them in the body
where the author put them.

Drafts written before this release keep the order they were generated with. Move the disclosure
line above the hashtags by hand, or generate again.

## Changed: the draft is editable where it is written

The post the generator produced was read-only until it reached the Library. A word to change or
a line to cut is the normal case, so fixing it meant saving first and editing somewhere else —
and while the text sat there uneditable, everything on the composer screen went on describing a
draft nobody was going to publish.

The draft box on all three post screens is now an editable field. The Bluesky byte counter, the
Mastodon character count against the instance's limit, the image prompt, the hashtag
suggestions, Copy, Send to Engage and Send to Library all read the same text, so an edit reaches
every one of them.

The Save control had to become more careful in the same breath. "Saved to Library ✓" was
unarguable while the text could not change; with an editable draft it could sit on a tick while
the words on screen were different. It now tracks what it actually saved, offers **Save changes
to Library** when the text has moved away from that, and updates the entry it already has rather
than filing a second one.

Library entries have always been editable in place, from the card's own reader.

## Verification

The complete backend suite passes: **280 tests**. Eleven are new and pin down where the
disclosure sits: before a trailing hashtag line, after everything when there is none, unmoved by
a hashtag inside a sentence, and behind a closing line written under the tags. Mastodon's
extraction rule was read from its published source rather than inferred from how a post looked.

Electron's main process and renderer pass TypeScript checking, and the production desktop bundle
builds successfully.

No live social post was made while verifying this release.

## Installing

These installers are unsigned. Windows SmartScreen and macOS Gatekeeper will both warn about
that — expected, not a sign anything is wrong. On Windows choose **More info → Run anyway**;
on macOS, right-click the app and choose **Open**.
