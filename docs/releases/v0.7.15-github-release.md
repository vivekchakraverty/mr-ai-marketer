The Email Writer works out of the box, and the Blog Writer can finally be pointed at a Space
from inside the app.

## Fixed: the Email Writer had no reachable way to be configured

Every generation refused with "Email Writer needs its own Hugging Face Space — set
EMAIL_WRITER_SPACE in your environment (or backend/.env)". In an installed build that
instruction cannot be followed: there is no `backend/.env`, only a packaged executable, and
nothing in the app could write an environment variable. The tool was unreachable rather than
broken, and said so in a way nobody could act on.

The Blog Writer had exactly the same gap. Both are fixed the same way Brand Studio and the
Marketing Plan already were: **Settings now has a field for each**, handed to the backend when
it starts. The backend reads these at startup, so the app needs restarting after saving —
which the section says.

The Email Writer additionally now points at a working public Space by default, so it writes
something the first time it is opened instead of refusing until it is configured. That default
is the maintainer's own deployment and the trade falls on that account; a fork should set its
own, from Settings or from `EMAIL_WRITER_SPACE`, both so its generations are its own and so
that one is not answering for it. The Blog Writer keeps no default, because there is no public
Space to point it at.

## Fixed: the Email Writer would have failed on every call

The Space request is now authenticated with your Hugging Face token, which is what lets a
Space be private and what identifies a caller. The first version of that change passed the
token under the wrong name: `gradio_client` renamed the argument, and the installed version
rejects the old one outright rather than ignoring it — so every Email Writer call would have
raised a TypeError. Caught before release, and worth recording because no test covers it: the
suite does not call the Space.

Two smaller things fell out of the same change. Clients are cached per token rather than
globally, so a changed token opens a new connection instead of reusing a session authenticated
as somebody else. And the token falls back to the backend's own `HF_TOKEN` when a caller does
not supply one — not a convenience: the Lead Gen Agent drafts outreach through this same
service and its injected writer takes only an instruction, so without the fallback a private
Space would have refused every outreach draft while the Email Writer screen carried on working.

## Note: the Email Writer Space now refuses some briefs

The Space this tool calls is public and free, so it has gained two guards of its own. They are
not in this app and apply to every caller.

A **rate limit** of ten emails an hour per caller. Not about cost — a free CPU Space costs
nobody anything — but about the queue: a 7B model on two shared vCPUs takes one to three
minutes per email, so one caller in a loop makes it useless for everyone else.

A **refusal** for briefs that plainly ask for illegal email — phishing, malware, counterfeit
documents and the like. It matches intent rather than lone words, because "reset your password"
is ordinary transactional email and only impersonation makes it phishing. It is a speed bump on
an open endpoint, not a moderation system: careful phrasing gets through, and it is described
that way rather than oversold.

## Verification

The complete backend suite passes: **290 tests**. Electron's main process and renderer pass
TypeScript checking, and the production desktop bundle builds successfully.

The Space guards were exercised against fourteen briefs before deploying — two failed and were
fixed, one of them a pattern that refused an honest brief, which is the failure a real user
meets. Both paths were then tested against the deployed Space: a phishing brief refused
immediately, and an ordinary sale email written in 84 seconds.

No live social post was made while verifying this release.

## Installing

These installers are unsigned. Windows SmartScreen and macOS Gatekeeper will both warn about
that — expected, not a sign anything is wrong. On Windows choose **More info → Run anyway**;
on macOS, right-click the app and choose **Open**.
