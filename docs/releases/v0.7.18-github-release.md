A build fix: writing an email no longer loads the scoring stack before there is anything to
score.

## Fixed: the Email Writer service pulled in numpy, scikit-learn and joblib to import

`services/email_writer` imported the click-through predictor at module scope, and that module
imports numpy, scikit-learn and joblib. So anything that touched the Email Writer — including
the Lead Gen Agent, which drafts outreach through the same service — loaded the whole scoring
stack whether or not a score was ever produced.

That import is now made inside the function that scores. Nothing above that line needed any of
it, and the module can now be imported where that stack is absent.

The visible symptom was in continuous integration rather than in the app: the test suite there
runs against a deliberately minimal dependency set, without numpy, and a new test importing
this service failed to collect. The two previous releases were affected. Their installers were
unaffected and built cleanly — a packaged build carries the full dependency set — and neither
was published.

## Verification

The complete backend suite passes: **297 tests** locally, and **296 passed with 1 skipped**
against a virtual environment built to match continuous integration's dependency list exactly,
numpy absent. That second run is the one that matters here: the full development environment
has every package installed, so it cannot detect an import-weight regression at all, which is
why this reached two releases before being noticed.

Electron's main process and renderer pass TypeScript checking, and the production desktop
bundle builds successfully.

## Installing

These installers are unsigned. Windows SmartScreen and macOS Gatekeeper will both warn about
that — expected, not a sign anything is wrong. On Windows choose **More info → Run anyway**;
on macOS, right-click the app and choose **Open**.
