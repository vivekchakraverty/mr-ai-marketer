Pictures, everywhere they were missing: attached to the posts you send, kept on the Library
shelf, and offered in the compose boxes that could already write the words but never carry
the image.

It follows 0.6.1 normally — if you are on 0.6.1, this is one release's worth of change.
Anyone still on an older build gets everything since, including the resolution ladder for
posting times, Tumblr's generator, the Marketing Plan's move onto a Space, and the Keyword
Surfer collector with the plan built on it.

## Attach an image to a post you send

Engage's compose box now takes a picture. Under the text area there is a strip of the images
this app has generated — click one to attach it, and an alt-text field appears beside it.

Each network gets its own upload path, because each takes media differently:

| Network | How the image lands |
|---|---|
| Bluesky | `send_images`, so the embed is built by the SDK rather than by hand |
| Mastodon | Uploaded to your instance first, then referenced by the post |
| Tumblr | A multipart NPF post with the image block **above** your text |

Tumblr's ordering is deliberate. NPF block order is exactly what a reader sees, and on a
visual dashboard a picture underneath the caption reads as an afterthought.

Only images this app generated can be attached, and a file that fails that check is refused
before anything is uploaded — with a message you can read, rather than a failure halfway
through publishing.

## Generated images stay on the Library shelf

Brand Studio drew its logo mark, mood board and social header, saved them to disk, and told
nobody. There was no Library row for any of them, so they could not be reopened later and
never appeared in the picker above. Each asset now files itself as it is drawn, with the
prompt that produced it stored alongside.

Library cards show a thumbnail when the item is a picture. Four mood boards used to be four
identical-looking cards.

## The Bluesky Post Creator writes Bluesky posts

It used to offer X, LinkedIn and Mastodon as well. But everything it knows comes from the
Bluesky corpus — the exemplars are Bluesky posts, the engagement that ranked them is
Bluesky's, and the timing curve is measured on Bluesky authors. Drafting "for LinkedIn" from
that evidence dressed a Bluesky post in another network's name.

The platform picker is gone. Mastodon and Tumblr have their own creators, each grounded in
its own measured data.

## Posting times: no more dead ends

Because that screen offered Mastodon without having anywhere to name a server, its "when to
post" panel could only ever say *pick the server you're posting to first* — on a screen with
no server box to pick one in, and no way to fix it. The panel now stays silent when it has
no question it can answer, rather than giving advice about a step you cannot take.

The Mastodon Post Creator's panel is unaffected and reads the curve for your instance as
before.

## Fixed

- **The test suite wrote to your real Library.** Generating an image files it on the shelf,
  and the image-generation tests reached that code — so every run left rows in the actual
  database. Isolation is now automatic rather than opt-in. If you see stray rows about
  reviewing campaigns, they came from this and are safe to delete.
- An oversized attachment reported its size to one decimal place, so a 16.4MB file no longer
  reads as "16MB, past the 16MB limit".

## Installing

These installers are unsigned. Windows SmartScreen and macOS Gatekeeper will both warn about
that — it is expected, not a sign anything is wrong. On Windows choose **More info → Run
anyway**; on macOS, right-click the app and choose **Open**.
