A finished post now travels in one piece — words, hashtags and picture — from the creator
that wrote it to the composer that sends it.

## Send to Engage

Each post creator has a new button under the draft:

> **Send to Engage (with 2 tags + image) →**

It opens the composer with the text and your chosen hashtags already joined, and the
generated image already attached. The button names what it is carrying, so you can see
what will arrive before you click it.

Previously only the words made that trip. The picture had to be found again in Engage's own
picker and the tags re-ticked from memory — with nothing on the Engage side to say which
ones you had chosen a moment earlier.

## It goes to the right composer

A Mastodon draft is written against that server's character limit and its rules; a Tumblr
one is written for a dashboard. So each creator hands its post to its own composer rather
than everything landing in the Bluesky box.

## It fills the box, it does not send

The post is put in front of you with the cursor in it. Sending stays something you do,
having read what is about to go out — the same rule as the image prompts, which are proposed
for you to edit rather than drawn behind your back.

## Smaller things

- The Bluesky creator had an older **Send to Engage** that carried only the text. It is gone;
  two buttons with the same name and different payloads is worse than either alone.
- Hashtags are appended to a post the same way no matter which screen sent it, so they never
  appear to move between the creator and the composer.

## Installing

These installers are unsigned. Windows SmartScreen and macOS Gatekeeper will both warn about
that — expected, not a sign anything is wrong. On Windows choose **More info → Run anyway**;
on macOS, right-click the app and choose **Open**.
