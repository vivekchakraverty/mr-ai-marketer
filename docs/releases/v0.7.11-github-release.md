The Social Post generator's learning loop was recording drafts and measuring nothing. It now
traces a published post back to the draft that wrote it, by itself.

## Fixed: the learning loop was never closing

The Bluesky generator judges itself against posts that actually went out — `jobs/snapshot.py`
re-reads their engagement at the 1h, 24h and 48h marks, and the watchdog scores the system
against them. All of that only applies to a generation carrying the URI of the post it became.

Setting that URI required a call the app never made. Ninety-four drafts had been generated and
**none** was linked to a published post, so an hourly measurement job had been running against
an empty set for as long as the tool has existed. Nothing was broken in a way anything reported;
the loop simply had no input.

Nothing in the app joined the two halves. A generation lives in the corpus database and knows
nothing about Library entries; a distribution job knows its Library entry and, once sent, the
real post — but not which draft produced the words. That edge did not exist.

It does now, recorded when the draft is generated, which is the one moment both identities are
in the same place. Afterwards a sweep on the distribution scheduler's existing tick finds drafts
whose send has landed, reads the published URI from the automation run, and links them. A post
published through Distribute is traced back to its draft within about half a minute, with
nothing to press.

Two deliberate choices. The sweep runs **after** publishing rather than during it: linking needs
a network call to confirm the post exists, and a slow or failed lookup in the middle of a send
would be reported as a publishing failure, which it is not. And it costs nothing — not even an
import — when there is nothing to link, so a person who never opens the generator does not pay
for it on every scheduler tick.

Bluesky only. The Mastodon and Tumblr generators have their own loops with their own measurement
paths; this was the one that was never connected.

## What this does not do

Nothing is linked retroactively: drafts generated before this release carry no link, so posts
already published stay unmeasured.

And this banks data rather than changing what the generator writes. Measurements on a small
account will read zero, and that is the honest state of things — a post's engagement cannot
distinguish good writing from bad until there is an audience to register the difference. The
loop is being connected now so that a signal exists when there is one to record.

## Verification

The complete backend suite passes: **269 tests**. Ten are new and weighted toward the cases where
a link must *not* be made — a draft nobody sent, a send that has not landed, a run reporting no
post, and another channel's send being mistaken for this one — along with idempotency, so a
second sweep does no work, and regenerating into the same entry following the newest draft.

Electron's main process and renderer pass TypeScript checking, and the production desktop bundle
builds successfully.

No live social post was made while verifying this release.

## Installing

These installers are unsigned. Windows SmartScreen and macOS Gatekeeper will both warn about
that — expected, not a sign anything is wrong. On Windows choose **More info → Run anyway**;
on macOS, right-click the app and choose **Open**.
