The Mastodon generator can now learn from your own posts, and cancelling a scheduled post no
longer leaves the date picker unable to open.

## Added: a Mastodon post of yours that did well becomes one of the examples

The generator does not have a memory that gets tuned. Each time it writes, it is shown a
handful of real posts that performed in your niche and told to write something like them —
change the examples and the writing changes, and nothing else about it moves. Until now those
examples were always other people's posts, however well or badly your own did.

Two pieces were missing, and both are here.

**The app now knows which posts it wrote.** A Mastodon draft records which Library entry it
became, and the distribution scheduler traces a published toot back to that draft on its
existing tick. There was already a way to do this by hand — paste the post's link and hand
over an access token, because a URL is not addressable and the instance has to resolve it —
and it required remembering to do so every time. Nothing ever did. The automatic path needs
no token at all: the app published the post, so it has the status id, and a public status
reads back without one. Both paths run the same code, so a link made automatically lands
exactly as one made by hand.

**Your best qualifying post now holds a slot in the pool.** It has to be reserved rather than
won, and the reason is arithmetic: ranking divides interactions by followers plus a prior of
292, so on a young account a post that did genuinely well still scores near zero beside posts
that did well for accounts with thousands of followers. Without the reservation the generator
would never once be shown something that worked for the person using it.

It is not a way past the eligibility floors. A post still needs at least two interactions and
real prose to qualify — a post nobody reacted to gets no slot, because reserving one for a
flop would teach the generator to write like a post that did not work, which is precisely what
those floors exist to prevent. When nothing qualifies, the pool is left exactly as it was.

Bluesky is deliberately left out for now. Its pool is built by the vendored standalone project,
which this app keeps unmodified on purpose, so the same change there is an architectural
decision rather than an addition. Tumblr has had this since it was built.

## Fixed: the date picker froze after cancelling a scheduled post

Schedule a post, cancel it, and the date field in the send dialog would stop opening — while
the rest of the app carried on working normally.

Cancelling asked for confirmation through a native browser dialog. That dialog and the date
picker are the same kind of window underneath, and putting one up could leave the other unable
to open. The page kept responding because nothing was blocking it; only the picker was gone.

Cancelling now confirms in the row itself — the × becomes "Cancel this post? Yes / Keep" — so
no native dialog is created and nothing can be left in that state. It also removes a smaller
problem nobody had reported: that dialog froze the entire app for as long as it was on screen.

Similar confirmations remain in Engage and the Mastodon and Tumblr panels, and could still
affect the picker the same way. They are unchanged here.

## Verification

The complete backend suite passes: **290 tests**. Six are new and pin the reserved slot down:
the best qualifying post takes a slot, the pool trades an entry rather than growing, a post
that cleared no floor gets nothing, a post that already earned its place is not reserved twice,
the better of two own posts wins, and an empty pool stays empty.

One of those tests caught a real defect before release — on a niche holding fewer posts than
the pool target, the first implementation added an entry instead of trading one, quietly
growing what rides in the prompt.

Electron's main process and renderer pass TypeScript checking, and the production desktop
bundle builds successfully.

No live social post was made while verifying this release.

## Installing

These installers are unsigned. Windows SmartScreen and macOS Gatekeeper will both warn about
that — expected, not a sign anything is wrong. On Windows choose **More info → Run anyway**;
on macOS, right-click the app and choose **Open**.
