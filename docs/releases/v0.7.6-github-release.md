Media selected in Distribute now reaches the social post itself, not only Send History.

## Fixed: Distribute said an image was sent, but the timeline showed text only

The Distribute screen could show the complete post — text, hashtags and an image URL — and
mark the job *Sent*, while Bluesky published only the text.

The history was accurately showing what the app handed to its automation engine. The
missing piece was inside the already-published automation: Activepieces keeps an enabled
flow from the first time it was installed, and the app treated "enabled" as "up to date".
That older Bluesky flow passed only the account and text into the final action, so the
network was never given an image embed at all.

Bluesky and Mastodon flows now compare themselves with the version bundled in the app and
upgrade in place when their media inputs change. Bluesky also receives images in the array
shape its current connector requires. Existing account connections are retained.

This completes the earlier 0.7.4 repair. That release reopened the private bridge the
engine uses to fetch local images; this release fixes the second independent fault, the
stale flow that never asked the engine to use the fetched image.

## Fixed: local media survives restarts, schedules and renamed files

The private media listener now verifies that it really opened, follows the current WSL
gateway instead of a hostname mapping that can go stale, and retries discovery in the
background if Windows or WSL is still starting.

An immediate send is refused with a useful error if its local attachment cannot be served.
It will no longer quietly continue as a text-only success.

Scheduled posts keep the durable local media path and create a short-lived signed link only
when the post actually fires. Jobs that became due while the posting engine was starting
wait for the next scheduler pass instead of failing permanently. Scheduled jobs saved by an
older version can also recover and replace their expired legacy link. File names containing
spaces or non-ASCII characters now make the round trip correctly.

Send History keeps the durable attachment rather than an expiring transport URL, and for a
Bluesky job it shows the prepared image that was actually handed to Bluesky.

## Fixed: Bluesky images that are too large are prepared automatically

A generated local image can be perfectly valid and still exceed Bluesky's attachment cap.
The app now creates a cached, metadata-free WebP derivative when needed, preserving the
original Library image. It tries lossless conversion first and reduces quality or dimensions
only when necessary.

Pasted public image URLs are not downloaded by the app for security reasons, so the composer
now says plainly that those must already fit Bluesky's limit.

## New: attach a video from Distribute

The Distribute composer now accepts a staged video for Bluesky and Mastodon, including an
optional description for Bluesky. Image and video are mutually exclusive, and the selected
file is validated before a job is queued. If both networks are selected, the lower shared
size limit is applied. The current Mastodon connector does not expose an alt-text field, and
the composer says so rather than implying that the Bluesky description will be sent there.
Removing or replacing a video also clears its old description, so accessibility text cannot
accidentally follow the wrong clip.

Opening Distribute from a Library item now carries that item's image into the composer
automatically.

## Upgrading

There is nothing to reconnect. Restart the app and open Distribute; the bundled Bluesky and
Mastodon flows refresh automatically. Pending scheduled image jobs are upgraded when they
fire as long as their original local file still exists.

If you deliberately edited either bundled Bluesky or Mastodon flow inside Activepieces, this
upgrade replaces that built-in definition with the shipped version. User-added custom
channels and the other built-in channel flows are not changed.

## Installing

These installers are unsigned. Windows SmartScreen and macOS Gatekeeper will both warn about
that — expected, not a sign anything is wrong. On Windows choose **More info → Run anyway**;
on macOS, right-click the app and choose **Open**.
