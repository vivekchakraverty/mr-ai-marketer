A finished post is one card on the Library shelf, not two — and a momentary network blip no
longer takes the Mastodon composer away.

## Fixed: a generated image left a second card behind

Sending a post to the Library could still produce a pair: the post, and a card showing the
same picture with the post's opening line as its title.

They are not two copies of the post. A companion image files a Library row of its own the
moment it is drawn, because until the post is finished that row is the only place it lives.
The finished post then carries the same file, and the shelf ends up with two cards for one
picture — the fragmentation the composition save was written to end, from the one direction
it never covered.

Saving a composition now folds that row into itself: the finished entry keeps the picture, and
the standalone card for it goes. Matching is on the file **and** on the subtitle a companion
image is filed under, never the file alone — a Brand Studio asset picked into a post is still
an asset in its own right, and deleting it because a post borrowed it would lose something
nothing replaced. Its prompt text goes with the absorbed row, which is the cost of the entry
becoming one thing.

An image drawn *after* a composition is saved still files its own row until the composition is
saved again. Absorption happens when an entry gains a file, and nothing else should be able to
delete a picture from the shelf.

Cards already paired up are left alone; this stops new ones.

The separate case — a draft arriving as two text cards — was fixed in 0.7.9 and is confirmed
gone: of 166 entries on the test shelf, 18 groups shared a body, and none were created after
that release went in.

## Fixed: the Mastodon composer disappeared when the instance was slow

The composer is locked until the instance's rules have been read and accepted, and the screen
re-reads both the rules and the server's status whenever it refreshes. A failure there dropped
the accepted policy, which closed the gate and took away the entire composer — the niche
selector with it — over what was usually a moment of network trouble.

The rules on screen now survive a failed refresh. What was accepted is still accepted; only
naming a different server makes what is shown wrong, so that is the single case that clears it.
The error is still reported, rather than the controls quietly vanishing.

## Verification

The complete backend suite passes: **284 tests**. Four are new and cover the boundary
absorption has to respect: a companion image is folded in, a Brand Studio asset on the same
file is not, a companion image for a different file is untouched, and a save carrying no
attachment absorbs nothing.

Electron's main process and renderer pass TypeScript checking, and the production desktop
bundle builds successfully.

## Installing

These installers are unsigned. Windows SmartScreen and macOS Gatekeeper will both warn about
that — expected, not a sign anything is wrong. On Windows choose **More info → Run anyway**;
on macOS, right-click the app and choose **Open**.
