# Mr. AI Marketer 0.6.0

The Marketing Plan generator gets three things: somewhere else to run, a way to keep
what it produces, and keyword numbers that are actually measured.

---

## The plan can generate on a Space

Set **Settings → Marketing Plan Space** (or `MARKETING_PLAN_SPACE`) and the whole
pipeline moves off your machine: keyword research, the SEO, social and paid-ads
plans, the composed strategy, and the retrieval that grounds it. There is no
**1.1 GB** index to download and nothing to warm up at startup.

Leaving it empty is still a working configuration, and remains the default. The local
pipeline is untouched — a checkout with no Space configured builds plans exactly as it
did before, reference index and all.

Two things worth knowing before pointing it anywhere:

- **You are still billed for the models.** Your Hugging Face token travels with the
  request and inference runs on your account, exactly as it did locally. What is new is
  that the token leaves your machine to get there. A fine-grained, inference-scoped
  token is worth using unless the Space is your own.
- **What comes back is a plan, not a corpus.** The Space assembles its grounding
  internally and returns only the finished text.

The model dropdown now asks the backend what is on offer instead of listing what the
local pipeline supports, because a configured Space enforces its own model policy and
the old list could offer options that Space would reject.

## Every part of a plan is saved

A plan is five things, not one, and only the composed document was ever kept. Now all
of it lands on disk the moment a plan finishes:

| | Markdown | Word | Sheet |
|---|---|---|---|
| Complete plan | ✓ | ✓ | |
| Full strategy | ✓ | ✓ | |
| Keyword research | ✓ | ✓ | CSV + Excel |
| SEO plan | ✓ | ✓ | |
| Social plan | ✓ | ✓ | |
| Ads plan | ✓ | ✓ | |

Each section stands alone *and* appears in one combined document, because both are
real needs — the ads plan goes to whoever buys the ads, and the whole thing goes to
whoever signs it off. A **Save a copy** row under the plan opens any of them.

The keyword research also became a proper tab rather than a one-line note about where
the numbers came from.

> The markdown-to-Word renderer now lives in one place instead of two. Moving it
> surfaced two bugs that had been in the Brand Studio exporter: `**bold**` markers
> survived literally inside table cells, and the row parser split on escaped pipes,
> shearing rows into phantom columns. Both are fixed for both tools.

## Keyword Surfer, in a browser you can see

**Marketing Plan → Keyword Surfer** is a new tab that collects real search volumes,
CPC and related keyword ideas.

Keyword Surfer publishes its numbers only inside a browser on a real Google results
page, so reading them means driving one — and Google answers a *hidden* automated
browser with a captcha page carrying no results at all. That was measured from a
datacenter address and from ordinary home broadband, with the automation tells masked
and a real window on screen. Hiding harder does not fix it.

So this does the opposite. It opens a visible Chromium with the extension loaded and a
profile of its own, searches your keywords one at a time with a cooldown between them,
and **when Google asks for a check it stops and waits for you** to complete it in that
window before carrying on. The profile is kept, so the next run is not asked again.

What you get per keyword: its own volume and CPC, plus related ideas with their volumes
and similarity. Progress is live, runs can be cancelled mid-cooldown, and the whole run
exports to CSV.

The extension is downloaded once into your data directory on first use rather than
shipped in the installer.

## Google Ads credentials now reach the keyword tier

If you have filled in **Settings → Google Ads API**, those credentials now travel with
each plan request, so the official tier runs against *your* account and quota. This is
the only source that returns measured `avg_monthly_searches` and real top-of-page bid
ranges; without it the sheet holds relative-interest buckets and blanks.

The API is free. The fiddly part is the refresh token, so there is now a script:

```bash
python scripts/google_ads/auth.py --client-id ... --client-secret ... --developer-token ...
```

It runs the consent flow, prints the refresh token, and — given a developer token —
calls the live API and lists the customer IDs your login can reach, which is both a
real end-to-end check and where the **Login customer ID** value comes from. See
[`scripts/google_ads/README.md`](../../scripts/google_ads/README.md) for the console
steps.

## Honest limits

- **The unattended Surfer pass is usually blocked.** A second, silent scrape still runs
  after a plan is generated and merges anything it can get into the keyword sheet
  without overwriting measured Google Ads numbers. It is unattended, so Google normally
  refuses it. **Settings → Keyword Surfer proxy** takes a residential proxy if you have
  one, with a **Test proxy** button that reports the exit address alongside the verdict.
  The tab above is the reliable way to collect Surfer data.
- **A plan Space and Google Ads credentials are both untested here against a live
  billing account.** The plumbing is verified end to end; the figures depend on
  credentials this build could not exercise.

---

## Upgrading

Nothing to migrate, and nothing changes unless you opt in. Without a Marketing Plan
Space configured the tool behaves exactly as it did in 0.5.6 — the new exports and the
Keyword Surfer tab work either way.
