A patch. Nothing new to look at — 0.5.0's features are all here, plus one fix that
matters if you use Distribute.

## Distribute could not send on any channel

**Every scheduled send in 0.5.0 failed** with an error naming the channel — for
example `No flow imported for channel 'bluesky'`. Nothing was posted.

The message pointed at the wrong thing. Activepieces held all ten channel flows,
published and enabled; the flows were never the problem. What broke was the app
finding the *templates* that map a channel name to its flow.

That path was worked out by walking up from the backend's own source file — correct
when running from a checkout, wrong in the shipped app, because packaging changes
where that file appears to live. The app looked inside its own backend folder
instead of alongside it, and that directory does not exist. An empty template
directory means an empty channel map, and an empty channel map means *every*
channel is unknown — so the failure was total rather than Bluesky-specific. Bluesky
was simply the only channel connected.

It failed quietly, too, and in a shape that sent you looking in the wrong place: a
missing directory raised nothing on its own, and the first symptom was a
per-channel complaint that reads as "Activepieces did not import this flow", which
points into the engine, where everything was fine.

The app now checks the packaged location as well as the source one, accepts an
`ACTIVEPIECES_FLOWS_DIR` override, and says so loudly in the log when it cannot
find the templates at all. The error text also separates "templates are missing
from this install" — a packaging fault — from "this channel's flow did not
import", and lists the templates it can actually see.

> **If a send failed while you were on 0.5.0**, its job is still in Send history
> marked failed. Nothing retries on its own — re-send it once you are on this
> build.

## Also

CI's test-dependency list gained the OAuth library the Tumblr tests reach through
the Tumblr API service. No effect on the application.

## Upgrading

Nothing to migrate, and no reason to rush unless you use Distribute — in which case
this is the difference between sends working and sends failing.

Everything in [0.5.0's notes](https://github.com/vivekchakraverty/mr-ai-marketer/releases/tag/v0.5.0)
still applies: open the Tumblr Post Creator and press **Import** once, and the
Mastodon pools rebuild themselves on their next collection.
