Keyword Surfer's collector browser refused to open with an error that said nothing at all —
just `NotImplementedError:` and a blank line. This fixes it.

## Why it happened, and why it looked random

The collector drives a real browser, and starting that browser means starting a separate
program. On Windows, Python can only do that on one of its two internal networking modes —
and one of the libraries this app uses switches the whole program to the other one the
moment it loads, as a workaround for a problem of its own.

That library is the one behind **Brand Studio and image generation on your own GPU**. It is
loaded only when you first use one of those features, and the switch lasts until the app is
restarted.

Which produced a genuinely confusing pattern:

- Open the app, go straight to Keyword Surfer → the collector opens.
- Generate a brand asset or an image first, then go to Keyword Surfer → the collector never
  opens again until you restart.

Nothing in between looks related, which is why this survived a previous round of fixes: it
never reproduced in isolation.

## The fix

The collector now asks for the mode it needs for the moment it takes to start the browser,
then puts back whatever was there. Both features keep the behaviour they want, and the order
you happen to use them in stops mattering.

Verified with the failing condition deliberately in place — the collector opens and reports
no error.

## In the meantime

If you are on an older build: restart the app and open Keyword Surfer **before** using Brand
Studio or image generation, and the collector will open normally.

## Installing

These installers are unsigned. Windows SmartScreen and macOS Gatekeeper will both warn about
that — expected, not a sign anything is wrong. On Windows choose **More info → Run anyway**;
on macOS, right-click the app and choose **Open**.
