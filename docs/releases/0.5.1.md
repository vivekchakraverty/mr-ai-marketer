# Mr. AI Marketer 0.5.1

A patch. Nothing new to look at — 0.5.0's features are all here, plus one fix that
matters if you use Distribute, and one that only affects the project's own CI.

---

## Distribute could not send on any channel

**Every scheduled send in 0.5.0 failed**, with an error naming the channel — for
example `No flow imported for channel 'bluesky'`. Nothing was posted.

The message pointed at the wrong thing. Activepieces held all ten channel flows,
published and enabled; the flows were never the problem. What broke was the app
finding the *templates* that map a channel name to its flow.

That path was worked out by walking up from the backend's own source file, which
is correct when running from a checkout and wrong in the shipped app: the packaging
step rewrites where that file appears to live, so the app looked inside its own
backend folder instead of alongside it, and the directory it looked in did not
exist. An empty directory meant an empty channel map, and an empty channel map
means every channel is unknown — so the failure was total rather than
Bluesky-specific. Bluesky was simply the only channel connected.

It also failed quietly and in a shape that sent you looking in the wrong place. A
missing directory produced no error of its own; the first sign was a per-channel
complaint that reads as "Activepieces did not import this flow", which points into
the engine, where everything was fine.

Now the app checks the packaged location as well as the source one, accepts an
`ACTIVEPIECES_FLOWS_DIR` override, and says so loudly in the log when it cannot
find the templates at all rather than leaving Distribute mysteriously refusing
everything. The error text also separates "templates are missing from this
install", which is a packaging fault, from "this channel's flow did not import",
which is not — and lists the templates it can actually see.

**If a send failed while you were on 0.5.0**, its job is still sitting in Send
history marked failed. Nothing retries on its own — re-send it once you are on
this build.

## Project CI

The test suite passes locally and failed on the 0.5.0 release commit. The Tumblr
tests reach the Tumblr API service, which imports an OAuth 1.0a signing library at
module level, and CI's test-dependency list — assembled by observing what a clean
environment actually needed, rather than by reading imports — had never needed it
before. Added.

No effect on the application. This is here only because the 0.5.0 release commit
carries a red badge as a result, and this release is the one that clears it.

---

## Upgrading

Nothing to migrate, and no reason to rush unless you use Distribute — in which
case this release is the difference between sends working and sends failing.

Everything in 0.5.0's notes still applies: open the Tumblr Post Creator and press
**Import** once, and the Mastodon pools rebuild themselves on their next
collection.
