Scheduled posts handed to your poster Space now go out on time far more often, instead of
waiting for the next time you happened to open the app.

## Fixed: a scheduled post could sit until the app was next opened

Cloud posting exists so a scheduled post goes out with the app closed. Your Space runs on
free Hugging Face hardware, which falls asleep when nothing is using it, and a sleeping Space
posts when it is next woken. It was supposed to keep itself awake by pinging its own address
every five minutes. That does not work: Hugging Face does not count a Space's own traffic as
activity, so the Space slept anyway.

The result was a post scheduled for 09:00 going out at 09:12 — the moment the app was opened
and nudged the Space awake. Nothing was ever lost, because a pass sends everything whose time
has passed rather than only what is due that minute. But "on time" quietly depended on the
app being open, which is the one thing cloud posting is meant not to need.

There is now a heartbeat that pings your Space from outside it, so it stays awake and its own
timer is what sends your posts. **It is off until you switch it on** — see below.

## Fixed: a post added while the Space was mid-check could be overlooked

To avoid re-reading the whole queue every minute, the Space remembers where it got to and
skips a check when nothing has changed. If you scheduled a post at the exact moment one of
those checks was running, the Space recorded that it had looked at your new post when it had
not, and then skipped every check until whatever else was in the queue came due — which could
be hours later, or the next day.

The window was narrow, a second or two per minute. It is now closed.

**If you use cloud posting, re-run Settings → Cloud posting → Reconnect credentials → Repair
this Space** to pick this up — your Space runs a copy of the code from the version that set it up.

## Fixed: a Space set up mid-session was never nudged

If you completed the cloud posting walkthrough without restarting the app afterwards, the app
would hand your scheduled posts to the new Space but never nudge it when one was nearly due,
because it was still looking for the Space in settings read at startup. Restarting fixed it,
which is why this went unnoticed.

## Switching on the heartbeat

This is a one-time setup on GitHub, and it is optional — everything else above works without
it.

1. Fork or clone this repository under your own GitHub account, if you have not.
2. Go to **Settings → Secrets and variables → Actions → Variables → New repository variable**.
3. Name it `POSTER_SPACE_URL` and set the value to your Space's address, which the app shows
   at Settings → Cloud posting (it looks like `https://yourname-mr-ai-marketer-poster.hf.space`).

That is all. A scheduled job pings your Space every fifteen minutes and keeps it awake. Until
the variable is set the job is skipped, so nothing runs and nothing fails. GitHub turns
scheduled jobs off on a repository with no activity for sixty days.

If you would rather not use GitHub, **cron-job.org** does the same thing: point it at your
Space's address with `/tick` on the end, every five minutes, notifications off. Either way
the address is safe to hand to a scheduler — it carries no post text, no schedule and no
account details, and all it can do is make your own due posts go out on time.

The most reliable fix remains upgrading your Space to paid hardware, which does not sleep at
all.

## Verification

The backend suite passes: **374 tests**, run against a virtual environment built to match
continuous integration's dependency list exactly. Electron's main process and renderer pass
TypeScript checking.

Three of those are new, and each was checked against the old code first to confirm it fails
there — a test that passes either way guards nothing. Two reproduce the overlooked-post bug
and the un-nudged Space; the third pins the behaviour the optimisation still has to have, so
the fix cannot quietly turn into a check on every tick.

The lateness itself was confirmed rather than assumed. Mastodon post identifiers carry the
time they were created, so every post this app has sent from the cloud could be read back and
compared against the minute it was scheduled for: on time on 5 and 6 September, twelve minutes
and forty-eight seconds late on 8 September, at exactly the second the app was opened.

Not verified: no scheduled post has yet gone out with the heartbeat running. That takes a day
of ordinary use to observe.

## Installing

These installers are unsigned. Windows SmartScreen and macOS Gatekeeper will both warn about
that — expected, not a sign anything is wrong. On Windows choose **More info → Run anyway**;
on macOS, right-click the app and choose **Open**.
