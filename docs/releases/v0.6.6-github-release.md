Two fixes worth installing for on their own — the Library screen could be taken down
entirely by a single saved item, and the app has never shown its own diagnostic logs — plus
a way to keep a finished post in one piece.

## Keep the post, its hashtags and its picture together

Post creators have a new **Send to Library** button at the foot of the screen. It writes one
entry: the post text with your chosen hashtags appended exactly as they would be published,
and the generated image as that entry's file.

The three pieces were already saveable separately, and that was the problem. The draft went
in through the Save button, the image filed itself the moment it was drawn, and the hashtags
lived nowhere but the screen — so a finished post arrived as two unrelated entries and a set
of tags you had to remember. Putting it back together later meant knowing which picture went
with which draft.

The button says what it is about to keep — *Send to Library (post + 2 tags + image)* — and
offers to save again whenever you change any of the three.

## Fixed: one saved item could break the whole Library

The Library screen showed **"This screen stopped working"** and nothing else. Any item whose
type had no colour assigned to it — a saved hashtag set, an Engage reply — crashed the card
that drew it, and a card that fails takes the entire screen with it rather than just itself.

Unknown types now get neutral styling and appear normally.

Two smaller things in the same area:

- **The Library did not reload when you opened it.** It only updated when whichever tool
  last saved something happened to push to it, so a save made elsewhere could be missing
  from a list that looked complete. It now re-reads every time it is opened.
- Library cards show a thumbnail when the item is a picture.

## Fixed: the app was throwing away its own logs

Nothing in the backend had ever configured logging, so every diagnostic line it wrote — the
posting-time collector, the Mastodon learner, the browser launcher — was produced and
immediately discarded. Warnings and errors still reached the console; everything explaining
what the background work actually did did not.

That is why a silent failure stayed silent. Those lines are now visible, which is what
turned the next item from a guess into an answer.

## The collector can be searched by hand

Keyword Surfer's collector browser is a real window you can type into, and searching in it
shows real figures on screen. Until now the app only recorded searches it ran for you from
the keyword list, so you could sit looking at volumes it reported nothing about.

Searches you run yourself in that window are now collected too, filed together as one
session. The region is read from the search you actually ran rather than assumed from the
app's country setting.

**Please treat this part as new and unproven.** The mechanism is in place and its groundwork
is tested, but a capture of a live search has not yet been observed end to end — the runs
that would have confirmed it kept failing for unrelated reasons. If it does not pick up your
searches, the keyword list still works exactly as before.

## Fixed: a crash could leave the collector unable to open

If the app was killed or crashed while the collector browser was open, the browser left a
lock file behind and every later attempt failed with *"profile is already in use"* — with no
way forward except deleting a file you would have no reason to know about. That leftover is
now cleared automatically when the collector starts.

## Character counts in Distribute

The Send to Distribution box counts characters against every channel you have ticked, names
the tightest limit in play, and tells you which channels the text is too long for.

It warns rather than blocks. Mastodon's 500 is the default a server ships with, not a rule —
instances routinely raise it, and this box does not know which server you are posting to, so
refusing a post on a number it is only guessing at would be worse than saying so.

## Installing

These installers are unsigned. Windows SmartScreen and macOS Gatekeeper will both warn about
that — expected, not a sign anything is wrong. On Windows choose **More info → Run anyway**;
on macOS, right-click the app and choose **Open**.
