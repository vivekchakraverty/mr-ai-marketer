# Mr. AI Marketer 0.5.4

Three fixes to things that looked like they worked. Scheduled posts now go out
whether or not you had the app open, a failed send tells you what it tried, and
"When to post" reads a Mastodon server in a way that can actually find posts on it.

---

## Scheduled posts no longer depend on you watching

The distribution engine only ran while the Distribute screen was open and you had
pressed the button on it. Anything scheduled fires against whatever is running at
that moment — so a post queued on Tuesday for 3:30 on Wednesday simply failed if
the app had been restarted in between.

It now starts with the app, in the background. The window opens immediately;
bringing up the engine takes the better part of a minute and nothing else needs it.

**It never installs anything.** Setting up Docker is a decision with consequences
for the whole machine and can require a reboot, so that stays behind the button on
the Distribute screen where you asked for it. Auto-start only starts what is
already there: a machine that has never set the engine up, or has no Docker, is
left alone rather than prompted. If it cannot start, the app opens anyway and the
Distribute screen explains it, as it already did.

---

## A failed send now says what it tried

Send history showed a channel, a status and a date. A failed row said "Failed" and
nothing else — exactly when you most need detail.

Rows now open when clicked. Everything shown was already recorded and simply never
surfaced:

- **the error**, first, when there is one
- **the exact text that went out**
- **the attached image**, if any
- **when it was queued, scheduled, and last changed**

One row opens at a time — these get read to answer a specific question, not
browsed side by side.

## "When to post" can find posts on a busy Mastodon server

It reported that mastodon.social had no usable public posts to learn from — about
the server with more of them than almost anywhere.

The curve only scores posts old enough to have settled, a day or so, and it was
reading the server's public timeline, which arrives newest-first. That timeline is
only as deep as the server is quiet: measured, six hundred posts covers 21 hours on
one server and 5 on another. On a busy server every post it hands back is newer
than the settle mark, so nothing survived. **The busier the server, the more
completely it failed** — the opposite of what it should do. Small servers "worked"
only because a few hundred posts there spans a month.

The timeline is now used to find *who* posts on a server; each author's own feed
supplies what they posted and when, which reaches back properly. Measured on a real
server: nothing became 4,857 scored posts from 117 authors.

**This does not promise you a curve.** The same measurement then scored 0.142
against a 0.30 confidence floor, and sampling more authors made it *worse* — which
is the check correctly reporting that the pattern is not really there. What changes
is that a refusal now comes with its numbers instead of claiming there was nothing
to look at.

## Upgrading

Nothing to migrate.

- The engine starts on its own from now on. If you had set it up, it will simply be
  running.
- Any send that failed while it was down is still in Send history — click it to see
  what it was, and re-send from your Library.
