The Marketing Plan generator gets three things: somewhere else to run, a way to keep what
it produces, and keyword numbers that are actually measured.

## The plan can generate on a Space

Set **Settings → Marketing Plan Space** and the whole pipeline moves off your machine —
keyword research, the SEO, social and paid-ads plans, the composed strategy, and the
retrieval that grounds it. No **1.1 GB** index to download, nothing to warm up at startup.

Leaving it empty is still a working configuration and remains the default: without a Space
the local pipeline builds plans exactly as it did before, reference index and all.

Your Hugging Face token travels with the request and inference runs on your account, as it
already did — but the token now leaves your machine to get there, so use a fine-grained,
inference-scoped one unless the Space is your own. What comes back is a plan, not a corpus.

## Every part of a plan is saved

A plan is five things, not one, and only the composed document was ever kept. Now the
complete plan, the full strategy, the keyword research, and the SEO, social and ads plans
each land on disk as **Markdown and Word**, plus one combined document, plus the keyword
table as **CSV and Excel**. A **Save a copy** row under the plan opens any of them.

Each section stands alone *and* appears in the combined document, because both are real
needs — the ads plan goes to whoever buys the ads, the whole thing goes to whoever signs it
off.

Moving the markdown-to-Word renderer into one shared place surfaced two bugs that had been
in the Brand Studio exporter: `**bold**` markers survived literally inside table cells, and
the row parser split on escaped pipes, shearing rows into phantom columns. Both fixed, for
both tools.

## Keyword Surfer, in a browser you can see

**Marketing Plan → Keyword Surfer** is a new tab that collects real search volumes, CPC and
related keyword ideas.

Surfer publishes its numbers only inside a browser on a real results page, and Google
answers a *hidden* automated browser with a captcha and no results — measured from a
datacenter address and from ordinary home broadband, with automation tells masked and a real
window on screen. Hiding harder does not fix it.

So this does the opposite: a visible Chromium with the extension loaded and a profile of its
own, one search at a time with a cooldown, and **when Google asks for a check it stops and
waits for you** to complete it in that window before carrying on. The profile is kept, so
the next run isn't asked again. Progress is live, runs cancel mid-cooldown, and everything
exports to CSV.

## Google Ads credentials now reach the keyword tier

Credentials from **Settings → Google Ads API** now travel with each plan request, so the
official tier runs against *your* account. It's the only source returning measured
`avg_monthly_searches` and real top-of-page bid ranges. The API is free; the fiddly part is
the refresh token, so `scripts/google_ads/auth.py` now runs the consent flow, prints one,
and — given a developer token — calls the live API to list the customer IDs your login can
actually reach.

## Honest limits

The second, *unattended* Surfer pass that enriches a generated plan is usually blocked by
Google. **Settings → Keyword Surfer proxy** takes a residential proxy if you have one, with
a **Test proxy** button that reports the exit address alongside the verdict. The tab above
is the reliable way to collect Surfer data.

A plan Space and Google Ads credentials are both untested here against a live billing
account — the plumbing is verified end to end, but the figures depend on credentials this
build could not exercise.

## Upgrading

Nothing to migrate, and nothing changes unless you opt in. Without a Marketing Plan Space
configured the tool behaves exactly as it did in 0.5.6; the new exports and the Keyword
Surfer tab work either way.
