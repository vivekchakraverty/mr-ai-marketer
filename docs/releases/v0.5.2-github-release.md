Three things you can see: every post can now have an image you actually directed,
anything in the Library can be edited where it sits, and **When to post** works on
the large Mastodon servers where it previously just said no.

## Companion images, with the prompt in your hands

All three post creators — Bluesky, Mastodon and Tumblr — gain an image section
under the draft.

A small model reads the finished post and proposes the picture. **That proposal
lands in an editable box, and nothing is drawn until you press Generate on wording
you have read.** Change anything you like first: image models fail in specific,
correctable ways — wider shot, lose the desk, warmer light — and a minute spent on
the sentence beats regenerating five times hoping for a different result.

This replaces how the Bluesky composer worked: it built the prompt internally and
drew in one click, so the only way to change the picture was to change the post.
Mastodon and Tumblr had no image generation at all.

The refusal is enforced underneath the screen, not just by it — the endpoint
rejects a request carrying no prompt, so there is no path in the app that renders
text you never saw.

**On cost:** the suggestion runs on a small model, not the large one that writes
your posts. A paragraph of art direction is a short, well-specified task, and
paying composer prices for it every time you wanted a picture would be waste you
could see on your bill. If that model is unreachable, you get the standard
direction with a line saying so — it is text you were going to edit anyway.

## The Library is editable

Everything on that shelf was read-only, and the "Open in editor" button did nothing
at all — so a saved post with a typo stayed a saved post with a typo.

Items now open into an editable box with an **Edit / Preview** toggle, and **save
themselves as you type**. No Save button on purpose: everything here is already
saved, so adding one would create a state the rest of the app does not have —
edited but unsaved — whose only discovery route is losing the edit by navigating
away.

Saving never reorders the shelf. And if an entry has a document beside it (a Word
file from Docs, say) you are editing the saved text while the file is left alone —
the screen says so.

## "When to post" now works on large Mastodon servers

It reported that no timing data had been collected for `mastodon.social`, and
pressing **Check** never changed that. The feature was not broken — it was locked
out.

The curve learns from a server's public local timeline, the only broad sample of
that server's own members. `mastodon.social` does not serve it to anonymous
callers; it answers *"this method requires an authenticated user"*. The app asked
without logging in, took the refusal, and reported that the server "does not serve
a public local timeline" — which reads as *this server has nothing* when the truth
was *this server wants you to log in*.

It now reads that timeline as you, using the Mastodon account the composer already
publishes with. When no account is connected it says which one to connect rather
than describing a failure. Smaller servers that serve it anonymously still work
without a login.

> Two things unchanged: the sample is still that server's own accounts only, because
> engagement counts are trustworthy only on the server hosting an account. And the
> reliability gate still decides whether a curve ships — **toot.garden will keep
> refusing**, for a reason no login can fix: 83 monthly members is too small a sample
> for any curve to reproduce on its own data.

## Upgrading

Nothing to migrate.

- **Press Check on your Mastodon server** once if you want a timing curve. Reading a
  month of a large instance takes a moment.
- Image sections appear under any draft you generate; nothing happens until you ask
  for a prompt.
