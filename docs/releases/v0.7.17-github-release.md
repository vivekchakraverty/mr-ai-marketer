A finished email is no longer thrown away because the click-through estimate beside it could
not be produced.

## Fixed: a missing click-through model failed the whole request

The Email Writer scores each draft with a small click-through model, shown in a card under
the email and labelled — accurately — as an estimate, not a guarantee. That model is
deliberately not in this repository: it sits alongside three other data files that were
removed when the repo went public, and the intended arrangement is that you host it yourself
and point Settings → Data repositories at it.

Until you have, there is no model. And an install in that state did not write emails without a
score; it refused, with an error about `HF_ASSETS_CTR_MODEL_REPO`. The email had already been
written by then — the model had run, the copy existed — and it was discarded on the way out
because an optional number could not be attached to it.

The estimate is now optional in fact as well as in description. If the model cannot be loaded,
the email comes back and the score card simply is not rendered. Configure a model repo and the
card returns exactly as before.

Nothing changes for an install that already has one.

## Setting one up

Put a Hugging Face repo holding `ctr_model.joblib` and `ctr_reference_stats.json` into
Settings → Data repositories. The backend reads it at startup, so restart the app after
saving. A private repo is fine — your own token reads it.

## Verification

The complete backend suite passes: **297 tests**. One is new and covers exactly the case that
lost work: with the click-through model unavailable, the email still comes back, with no score
and no bucket.

The path was also exercised for real rather than only in a stub: the model artifacts were
published to a private Hugging Face repo and loaded back with an empty cache and the local
copies moved aside, so the fetch and the prediction came from the Hub rather than from files
that only exist on a development machine.

Electron's main process and renderer pass TypeScript checking, and the production desktop
bundle builds successfully.

## Installing

These installers are unsigned. Windows SmartScreen and macOS Gatekeeper will both warn about
that — expected, not a sign anything is wrong. On Windows choose **More info → Run anyway**;
on macOS, right-click the app and choose **Open**.
