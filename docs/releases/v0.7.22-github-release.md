You can attach an audio file to a Mastodon or Bluesky post now — and Bluesky, which cannot
carry sound at all, gets a video of the waveform instead.

## Added: audio attachments

The upload button on the Bluesky and Mastodon composers now takes a sound file as well as a
clip: mp3, m4a, aac, wav, flac, ogg, oga or opus. It works everywhere a video already did —
post now, schedule for later, or hand it to your poster Space to go out with the app closed.

Mastodon takes audio natively and shows a player, so it receives the file exactly as you
chose it.

Bluesky has no way to carry sound. Its posts can embed images, a video, a link card or
another post — there is no fifth kind, and nothing to enable. So the app renders your audio
into a square video: the waveform drawn in the app's own colours, with your file as the
soundtrack. That happens on your machine while you watch the send dialog, and the composer
says it will happen before you pick the file rather than leaving you to wonder afterwards
why your Bluesky post is a video.

Send to both at once and each network gets the version that suits it — the sound file to
Mastodon, the rendered clip to Bluesky — from the one post you wrote.

Two limits worth knowing. Bluesky takes up to ten minutes, and audio longer than that is
refused before anything is rendered, with the length named, so you are not left waiting for
a conversion that was never going to be accepted. Tumblr's composer still offers video only:
its posts describe audio differently and that is not wired up.

## Fixed: Bluesky video was capped at 50MB, which has not been true since 2025

Bluesky raised its video limit twice — to three minutes, and on 26 August 2026 to **ten
minutes and 300MB**. This app was still refusing anything over 50MB and telling you that was
Bluesky's rule. It was not. Clips the network would have accepted were being turned away
here, before an upload was even attempted.

The ceiling is now 300MB and ten minutes, and the message quotes the real figure.

## Fixed: some audio would have been refused by Mastodon over its content type

Attachments sent from your poster Space are labelled with a media type, which the Space used
to work out from the file's extension using the operating system's own table. That table
disagrees with Mastodon for two formats: it calls `.flac` audio/x-flac and `.aac`
audio/vnd.dlna.adts, and Mastodon accepts neither. Those uploads would have been rejected by
the instance with nothing obviously wrong at this end.

The Space now states the type from a table checked against Mastodon's own list. **If you use
cloud posting, re-run Settings → Cloud posting → Repair this Space** to pick this up — your
Space runs a copy of the code from the version that set it up. Without it, mp3, wav, ogg and
m4a are unaffected; only flac and aac would fail.

## Verification

The backend suite passes: **371 tests**, run against a virtual environment built to match
continuous integration's dependency list exactly. Electron's main process and renderer pass
TypeScript checking.

Thirty-three of those tests are new. Twenty-five cover audio — that a file outside the app's
own storage is refused, that a send to both networks hands each one the right file, and one
that runs the real ffmpeg and checks the result is a video with a sound track. That last one
earned its place immediately: it caught a bug no mocked test could have, where the temporary
file had no extension for ffmpeg to infer a format from. The other eight cover the poster
Space, including the media types above.

Beyond the suite, the whole send path was run on real ten-megabyte audio files. One at 128
kbps, which is ten and a half minutes long, was refused for length in a third of a second.
One at 192 kbps was accepted, rendered in 68 seconds, and produced exactly what each network
needed.

Not verified: no audio post has been published to a live Mastodon instance or Bluesky account
yet. Everything above stops at the network boundary.

## Installing

These installers are unsigned. Windows SmartScreen and macOS Gatekeeper will both warn about
that — expected, not a sign anything is wrong. On Windows choose **More info → Run anyway**;
on macOS, right-click the app and choose **Open**.
