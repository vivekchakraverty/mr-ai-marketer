# Audience Personas discovery

- **UI:** Electron + React 19 + TypeScript. `App.tsx` routes to `routes/Research.tsx`; that screen keeps a local `ResearchTool` selector and renders tool components beneath its heading. New tool labels/headings and `<AudiencePersonas />` belong there. Shared beach-theme styles are in `styles/styleKit.ts` and CSS tokens in `styles/tokens.css`; controls must be responsive and keyboard native.
- **State:** Zustand in `state/store.ts` holds global navigation and plan fields. Tool components normally keep temporary form state. Personas need backend-persisted runs because local React state vanishes on restart.
- **Storage and migrations:** `backend/app/db.py` owns the SQLite file under `config.DATA_DIR` (`%APPDATA%/mr-ai-marketer` in Electron); startup `init_db()` executes `CREATE TABLE IF NOT EXISTS` and explicit column widening. JSON documents are an existing pattern (`tracker_docs`). Persona runs can store a versioned JSON document in a dedicated SQLite table. The backend's `db._connect()` gives short transactions and WAL.
- **API and jobs:** FastAPI routers are registered in `app/main.py`; renderer wrappers in `api/client.ts` use the per-session backend token. `game_analysis/jobs.py` uses a bounded `ThreadPoolExecutor`, SQLite status, polling and cancellation. Personas should follow that shape. `services/genqueue.py` is for generation slots, not persistent research jobs.
- **AI and spend:** Marketing plan and social generation use Hugging Face; the social-post HF router uses per-call accounting. Brand Studio can use Modal. The repo currently favors HF for generation, rather than the pasted prompt's Gemini/Ollama choices. Existing BGE embeddings and scikit-learn are dependencies, but importing model stacks at startup would be expensive. Persona analysis can be deterministic and offline first; no LLM call or spend logging is needed in its first implementation.
- **Collectors:** Bluesky and Mastodon API integration lives in `routers/engage.py` and `services/mastodon.py`; Bluesky analytics posts are persisted in `bluesky_analytics_posts`. Topic Scout has broader public-source collection. Persona collection must be bounded, consent gated and anonymous, not reuse account posting actions.
- **Secrets:** Electron's encrypted `settingsStore.ts` stores user credentials; the backend receives them at runtime. Do not persist keys in persona runs. A collector requiring a key should be disabled until a safe runtime handoff is wired.
- **Verification:** Python tests use pytest (`backend/app/tests`); frontend uses TypeScript typecheck plus `electron/scripts/verify-*.mjs` scripts. CI runs backend tests, typecheck, a calendar verifier and secret scan. Installer bundles the Python backend and Electron UI. The working tree already contains unrelated distribution-calendar edits; persona commits must stage only persona files.
